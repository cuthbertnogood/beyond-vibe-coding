## О чём статья

В последние годы порог входа в разработку резко снизился благодаря ИИ-инструментам (Cursor, Claude Code, GitHub Copilot). Появился феномен **«вайбкодинга»** — генерации кода по естественному языку. Это удобно для прототипов, но создаёт иллюзию, что разработка сводится к синтаксису.

На практике код сталкивается с ограничениями ОС, конкурентностью, сетевыми сбоями, безопасностью и необходимостью наблюдаемости. Без фундаментальной базы системы рушатся под нагрузкой.

## Пять ключевых пластов

### 1. Железо, ОС, память и ввод-вывод
Блокировка Event Loop синхронным I/O, дорогие системные вызовы, утечки дескрипторов (EMFILE), page faults и GC-паузы.

**Решение:** неблокирующий I/O (epoll/io_uring), вынос тяжёлых задач в воркеры, контроль RSS памяти.

### 2. Данные, типы, индексы и транзакции
Lost Update при параллельных списаниях, O(N²) и N+1 в ORM, использование float для денег.

**Решение:** DECIMAL/BigInt, UTC ISO 8601, правильные индексы (B-Tree/GIN), уровни изоляции ACID и locking (FOR UPDATE / Optimistic).

### 3. Сети и распределённые системы
Сеть ненадёжна (ложные предположения о сети).

**Паттерны:** таймауты, Exponential Backoff + Jitter, Circuit Breaker, идемпотентность (Idempotency-Key), понимание CAP/PACELC, Transactional Outbox.

### 4. Безопасность и лицензии
IDOR/BOLA, SQL-инъекции, утечки секретов, CORS-уязвимости, Slopsquatting (галлюцинации пакетов).

**Практики:** проверка ownership, параметризованные запросы, Argon2id/bcrypt, HttpOnly+Secure+SameSite cookies, фиксация хэшей в lockfile.

### 5. Архитектура, тестирование и наблюдаемость
Избегать Big Ball of Mud. Применять SOLID и Dependency Inversion, C4 Model + ADR.

**Наблюдаемость:** structured JSON-логи, перцентили p95/p99, RED-метод, OpenTelemetry distributed tracing.  
**Тесты:** пирамида + property-based testing.

## Главные выводы

- ИИ — это **экзоскелет** для инженера, а не замена фундаментальным знаниям.
- Вайбкодинг отлично подходит для прототипирования, но опасен в продакшене без понимания инвариантов отказоустойчивости.
- Настоящий разработчик обязан держать в голове архитектуру, отказоустойчивость и модели данных.
- Классические источники (Kleppmann, Nygard, Google SRE, Bryant & O’Hallaron) остаются актуальными.
- Без фундамента генеративный код накапливает технический долг, который сложно и дорого исправлять.
